4. Graph Model Explanation

SOURCE → STUDENTS → MENTORS → SINK
  • Source → Student capacity = 1 (each student can be allocated once)
  • Student → Mentor capacity = 1, only drawn between compatible pairs
  • Mentor → Sink capacity = mentor seat count
  • One unit of flow from source to sink represents one successful student-mentor assignment

5. Algorithms Used

Bipartite Matching

Purpose: Match two disjoint node groups using augmenting paths.

CampusFlow use: Baseline student-mentor matching before capacity-aware flow is applied.

O(V * E)

Edmonds-Karp

Purpose: Compute maximum flow using BFS to pick the shortest augmenting path.

CampusFlow use: Finds the maximum number of students that can be allocated to mentors.

O(V * E^2)

Max-Flow / Min-Cut

Purpose: Identify the saturated edges that limit further flow.

CampusFlow use: Explains exactly which mentors caused unallocated students.

O(V + E)

Min-Cost Max-Flow

Purpose: Among all maximum flows, choose the one with lowest total edge cost.

CampusFlow use: Maximizes allocation count, then improves preference satisfaction.

O(V * E^2) using Bellman-Ford

Dinic

Purpose: Compute maximum flow using level graphs and blocking flow.

CampusFlow use: Faster comparison algorithm for the same allocation problem.

O(V^2 * E)

6. Project Novelty

Reusable Optimization Engine

The same graph-based allocation model can be reused for mentors, electives, labs, classrooms, project guides and placement slots.

Explainable Allocation

The system explains why a student was allocated or unallocated using residual capacity and min-cut information.

Preference-Aware Allocation

Min-Cost Max-Flow can optimize preference quality in addition to allocation count.

Algorithm Comparison

Edmonds-Karp and Dinic can be compared using the same allocation dataset.

Bottleneck Analysis

CampusFlow identifies saturated resources and capacity shortages.

7. Adaptability

Student ↔ Mentor

Primary working scenario in this build.

Student ↔ Elective

Electives replace mentors, seat counts replace capacity.

Batch ↔ Lab

Batches replace students, lab slots replace mentors.

Course ↔ Classroom

Classrooms become capacity-limited resources.

Team ↔ Project Guide

Guides replace mentors, teams replace students.

Student ↔ Placement Slot

Placement slots become capacity-limited resources.

Only entities, capacities, compatibility and preferences change between scenarios. The core flow algorithm remains the same.
